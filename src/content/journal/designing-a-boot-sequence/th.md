ระหว่างหน้า HTML ดิบกับพอร์ตโฟลิโอ เว็บนี้เล่นลำดับภาพยาวห้าวินาทีที่ดูเหมือนจอภาพสูญเสียสัญญาณแล้วฟื้นกลับมา โดยไม่มีวิดีโอและไม่มี canvas ทั้งหมดคือ HTML, CSS keyframes และ React เล็กน้อยเพื่อวางชิ้นส่วน

## ไทม์ไลน์

ลำดับทั้งหมดอ้างอิงนาฬิกาเดียวที่เริ่มเมื่อ overlay ถูก mount ทุกอย่างถูกกำหนดเวลาเป็นมิลลิวินาทีนับจากจุดนั้น

| ช่วงเวลา | สิ่งที่เกิดขึ้น |
| --- | --- |
| 0 – 1.0 วินาที | หน้า raw เริ่มสั่น มีรอยฉีกแนวนอนเล็ก ๆ และขอบสีเหลื่อม |
| 1.0 – 2.5 วินาที | ความเสียหายเพิ่มขึ้น บล็อกพิกเซล ประกายไฟ และจอดำสั้น ๆ |
| 2.5 – 3.5 วินาที | สัญญาณหาย ขึ้น *NO SIGNAL* ภาพม้วนและยุบตัวแบบจอ CRT เก่า |
| 3.5 – 4.5 วินาที | เปิดเครื่อง กริดและโลโก้ประกอบกลับจากบล็อกเล็ก ๆ |
| 4.5 – 5.0 วินาที | สั่นครั้งสุดท้าย ขึ้น *SYSTEM RECOVERED* แล้วจึง reveal |

บางจังหวะแม่นยำมาก ภาพ raw หยุดถูกวาดที่ **2620 ms** และ *NO SIGNAL* ปรากฏในจังหวะเดียวกันเป็นเวลา 240 ms ภาพม้วนตั้งแต่ 2860 ถึง 3250 ms และการยุบตัวจบที่ 3550 ms หลังแสงเปิดเครื่องเริ่มที่ 3520 ms เพียงเล็กน้อย

## Keyframes ที่สร้างจากเหตุการณ์

glitch จะดูผิดถ้ามันลื่นไหล รอยฉีกและการกะพริบทุกชิ้นใช้ `steps(1, end)` เพื่อให้ค่ากระโดดแทนการค่อย ๆ เปลี่ยน ส่วนที่ยากคือความไม่สม่ำเสมอ keyframes ที่ห่างเท่ากันจะดูเป็นเครื่องจักร

ทางแก้คือเขียนแต่ละเอฟเฟกต์เป็นรายการเหตุการณ์ เช่น *ที่ 1460 ms เลื่อน 18 px, ที่ 1530 ms กลับที่เดิม* แล้วใช้สคริปต์เล็ก ๆ แปลงเป็น keyframes แบบเปอร์เซ็นต์ แอนิเมชัน 2620 ms ที่มีเหตุการณ์ห่างไม่เท่ากันจะได้ keyframes อย่าง `55.73%` และ `58.4%` ที่ไม่มีใครพิมพ์เอง และนั่นคือเหตุผลที่มันดูเป็นธรรมชาติ

## ภาพที่ฉีกคือหน้าจริง

รอยฉีกไม่ใช่ภาพหน้าจอ overlay แสดงสำเนาที่ถูกตัดของเอกสาร raw จริง แต่ละชิ้นเป็นแถบแนวนอนที่เลื่อนได้อิสระ และแต่ละสำเนาใช้ `all: initial` เพื่อไม่ให้สไตล์ของพอร์ตโฟลิโอรั่วเข้าไปในสิ่งที่ตั้งใจให้เป็นหน้าไม่มีสไตล์

## ความสุ่มที่เหมือนเดิมทุกครั้ง

บล็อกพิกเซล ประกายไฟ และแถบกะพริบ ถูกวางตำแหน่งด้วยตัวสร้างเลขสุ่มเทียมแบบมี seed (ตัวสร้าง Park–Miller แบบคลาสสิก) แทน `Math.random`:

```ts
function seeded(seed: number) {
  let s = seed;
  return () => {
    s = (s * 16807) % 2147483647;
    return (s - 1) / 2147483646;
  };
}
```

บล็อกแต่ละระลอกมี seed และช่วงเวลาของตัวเอง ช่วงเสียหายระหว่าง 1050 ถึง 2450 ms ช่วงวิกฤตระหว่าง 2500 ถึง 3350 ms และช่วงประกอบกลับระหว่าง 3550 ถึง 4100 ms ผลลัพธ์ดูวุ่นวายแต่เหมือนกันทุกครั้งที่เข้าชม ซึ่งทำให้ออกแบบและตรวจทานได้ทีละเฟรม

## ข้อจำกัดที่ต้องเคารพ

- **ไม่มีการกะพริบถี่** จอดำแต่ละครั้งสั้นและห่างกันหลายร้อยมิลลิวินาที และไม่มีแสงขาวเต็มจอกะพริบรัว
- **เคารพการตั้งค่าลดการเคลื่อนไหว** ถ้าระบบปฏิบัติการขอให้ลดการเคลื่อนไหว glitch จะไม่เล่นเลย หน้า raw จะตามด้วยการเฟดสั้น ๆ เข้าสู่พอร์ตโฟลิโอ
- **ข้ามได้เสมอ** มีปุ่ม *ข้ามอินโทร* บนจอตลอด และใส่ `?intro=skip` ใน URL เพื่อข้ามทั้งหมด ส่วนลิงก์ลึกไปยังหน้าภายในจะไม่แสดงอินโทรเลย
- **จอเล็กได้เวอร์ชันกะทัดรัด** มีองค์ประกอบน้อยลงแต่ใหญ่ขึ้น

## บั๊กด้านจังหวะเวลาที่ควรรู้

มีบั๊กสองตัวที่ปรากฏเมื่อแอนิเมชันเป็นของจริงแล้วเท่านั้น:

1. **เริ่มนาฬิกาเร็วเกินไป** ถ้า timer ของเฟสบูตเริ่มตอนที่ React ตัดสินใจแสดง overlay เวลาที่ใช้โหลด CSS จะถูกหักจากแอนิเมชันโดยไม่รู้ตัว ตอนนี้ timer เริ่มหลังจาก overlay แจ้งว่า mount แล้วเท่านั้น
2. **Reveal เร็วเกินไป** บนเครือข่ายช้า ห้าวินาทีอาจหมดก่อนพอร์ตโฟลิโอดาวน์โหลดเสร็จ การ reveal จึงรอทั้งสองอย่าง: `Promise.all([delay(5000), loadPortfolio()])`

เวอร์ชันก่อนหน้ายังเคยแสดงเทอร์มินัลวินิจฉัยปลอมที่มีบรรทัด log เลื่อนไปมาระหว่าง glitch ซึ่งถูกเอาออกแล้ว ความเสียหายทางภาพเล่าเรื่องได้ด้วยตัวเอง และ log ที่แต่งขึ้นไม่ควรอยู่บนเว็บที่ตั้งใจแสดงงานจริง
