เว็บนี้เริ่มต้นด้วยการทำเหมือนว่าตัวเองไม่ใช่เว็บไซต์ ในสามวินาทีแรกคุณจะเห็นเอกสาร HTML ธรรมดาในฟอนต์ Times New Roman ที่เป็นค่าเริ่มต้นของเบราว์เซอร์ ลิงก์สีน้ำเงินขีดเส้นใต้ และระยะขอบ 8 พิกเซล จากนั้นสัญญาณก็พัง แล้วอินเทอร์เฟซจริงจึงบูตขึ้นมา

แนวคิด *จาก HTML ดิบสู่ตัวตนดิจิทัล* นี้เป็นตัวกำหนดการตัดสินใจทางเทคนิคเกือบทั้งหมด บันทึกนี้จะเล่าทีละเรื่อง

## สามเฟส หนึ่ง state machine

แอปเคลื่อนผ่านสี่เฟส: `raw`, `boot`, `reveal` และ `ready` ทั้งหมดอยู่ใน reducer ขนาดเล็กใน `useBootSequence` และทุกการเปลี่ยนสถานะเดินหน้าได้อย่างเดียว:

```ts
case 'BOOT_DONE':
  return state.phase === 'boot' ? { ...state, phase: 'reveal' } : state;
```

เพราะ timer ที่หลงมาไม่สามารถย้อนสถานะได้ effect ที่รันสองรอบใน StrictMode หรืออุปกรณ์ที่ช้าจึงไม่ทำให้เว็บถอยกลับไปเฟสก่อนหน้า เฟสปัจจุบันยังถูกเขียนลง `<html data-phase="…">` ซึ่งสไตล์ชีตใช้เป็นขอบเขต

| เฟส | ระยะเวลา | สิ่งที่อยู่บนจอ |
| --- | --- | --- |
| raw | 3000 ms | เอกสาร HTML จริงที่ไม่มีสไตล์ |
| boot | 5000 ms | ลำดับ glitch |
| reveal | 700 ms | อินเทอร์เฟซกวาดเข้ามา |
| ready | — | พอร์ตโฟลิโอ |

## ไม่มี CSS เลยบนหน้าจอแรก

หน้า RAW จะได้ผลก็ต่อเมื่อไม่มีสไตล์ชีตใดแตะต้องมัน `index.html` ไม่ลิงก์ CSS เลย และโมดูลเริ่มต้นก็ไม่ import CSS ใด ๆ สไตล์ทั้งหมดของลำดับบูตและพอร์ตโฟลิโออยู่ใน lazy chunk และทุก selector ถูกจำกัดขอบเขตไว้ที่ `.boot`, `.wave-app` หรือ `html[data-phase]`

การจำกัดขอบเขตนี้สำคัญกว่าที่คิด เพราะ chunk เหล่านี้ **ถูกดาวน์โหลดตั้งแต่ช่วง RAW** เพื่อให้บูตเริ่มได้ตรงเวลา แปลว่า CSS ของมันอยู่ในเอกสารแล้วขณะที่หน้า raw ยังแสดงอยู่ selector ที่จำกัดขอบเขตคือสิ่งที่ทำให้มันมองไม่เห็นจนกว่าจะถึงเวลา

## โหลดล่วงหน้าโดยไม่ใช้ Suspense

เครื่องมือที่ชัดเจนที่สุดสำหรับ lazy component คือ `React.lazy` แต่ที่นี่มันสร้างปัญหาจริง เมื่อ lazy component โหลดเสร็จ Suspense จะหน่วงการแสดงเนื้อหาราว 300 ms สำหรับแอนิเมชันห้าวินาทีที่ต้องเริ่มตรงกับจังหวะที่ timer ของ RAW หมด ความหน่วงนี้มากพอจะทำให้ไทม์ไลน์คลาดกัน

ทางแก้คือ hook เล็ก ๆ ที่โหลด chunk ให้เสร็จระหว่าง RAW แล้วเก็บตัว component ไว้ใน state เพื่อให้ mount ได้ทันทีเมื่อเฟสของมันเริ่ม:

```ts
function usePreloaded<P>(loader: () => Promise<{ default: ComponentType<P> }>) {
  const [component, setComponent] = useState<ComponentType<P> | null>(null);
  useEffect(() => {
    let alive = true;
    loader().then((mod) => alive && setComponent(() => mod.default));
    return () => { alive = false; };
  }, [loader]);
  return component;
}
```

timer ของเฟสบูตจะเริ่มก็ต่อเมื่อ overlay mount จริงแล้ว และการ reveal จะรอ chunk ของพอร์ตโฟลิโอ เครือข่ายที่ช้าจึงไม่ทำให้อะไรสั้นลง และไม่เคยเผยหน้าว่างเปล่า

## สองภาษา ตรวจสอบโดยคอมไพเลอร์

อินเทอร์เฟซแปลเป็นภาษาไทยทั้งหมด พจนานุกรมภาษาอังกฤษเป็น object ธรรมดา และ type ของมันคือสัญญาสำหรับทุกภาษา:

```ts
const en = { nav: { journal: 'Journal' /* … */ } };
export type UIStrings = typeof en;
const th: UIStrings = { nav: { journal: 'บันทึก' /* … */ } };
```

ถ้าข้อความภาษาไทยหายไป build จะล้มเหลว ส่วนเนื้อหาส่วนตัว (โปรเจกต์ ทักษะ ใบรับรอง) ใช้อีกรูปแบบ ภาษาอังกฤษอยู่ใน `src/data` และข้อความไทยเป็นค่าทับที่อ้างด้วย id ทำให้ลิงก์ รูปภาพ และโครงสร้างไม่ถูกทำซ้ำ

ภาษาไทยยังต้องการตัวพิมพ์ของตัวเอง อักษรไทยมีวรรณยุกต์ด้านบนและสระด้านล่าง เว็บจึงเพิ่มระยะบรรทัดเป็น 1.75 สำหรับภาษาไทย และเอาระยะห่างตัวอักษรที่ใช้กับตัวอักษรละตินออก

## ธีมที่ไม่กะพริบ

ธีมมืดเป็นค่าเริ่มต้น ธีมสว่างเป็นตัวเลือก ค่าที่บันทึกไว้จะถูกตั้งที่ `<html>` *ก่อน* React render ผู้เข้าชมที่เคยเลือกธีมสว่างจึงไม่เห็นเฟรมมืดก่อน สีทั้งหมดเป็น token ที่ประกาศบน `.wave-app` และธีมสว่างเพียงแค่ทับค่า token

## รูปภาพที่มีงบประมาณ

เดิมส่วนใบรับรองโหลดใบรับรองทุกใบที่ความละเอียดเต็ม เมื่อวัดในเบราว์เซอร์ กริดดาวน์โหลด **3,910,564 ไบต์** จากรูปภาพ 10 รูป

ตอนนี้สคริปต์ `sharp` สร้าง WebP สองขนาดของใบรับรองแต่ละใบ คือภาพย่อ 640 px สำหรับกริด และภาพพรีวิว 1600 px สำหรับตัวแสดงภาพ ไฟล์ต้นฉบับไม่ถูกแก้ไข และจะโหลดเฉพาะเมื่อกด *เปิดขนาดเต็ม* หรือ *ดาวน์โหลด* หลังเปลี่ยน กริดดาวน์โหลด **212,092 ไบต์** หรือลดลงราว 95% และภาพย่อทุกภาพมีขนาดคงที่พร้อม skeleton จึงไม่มีอะไรขยับระหว่างโหลด

## URL จริงสำหรับหน้าที่ลึกกว่า

กรณีศึกษา บันทึกนี้ และแล็บ ต่างมีที่อยู่ของตัวเอง เว็บนี้มีเส้นทางเพียงไม่กี่เส้น แทนที่จะเพิ่มไลบรารีจัดการเส้นทาง จึงใช้ History API โดยตรง ร่วมกับ `useSyncExternalStore` เพื่อติดตามการเปลี่ยนตำแหน่ง Vercel rewrite ทุกเส้นทางไปที่ `index.html` และผู้เข้าชมที่เปิดลิงก์ลึกจะไปที่หน้านั้นทันที ส่วนอินโทร RAW เป็นของหน้าแรกเท่านั้น

## สิ่งที่ควรเก็บไว้

- **จำกัดขอบเขตทุกอย่าง** CSS ที่จำกัดขอบเขตทำให้โหลดล่วงหน้าได้เต็มที่โดยไม่ทำหน้าจอแรกพัง
- **ให้ระบบ type ดูแลคำแปล** ข้อความที่หายไปคือ build error ไม่ใช่ป้ายว่างเปล่า
- **วัดก่อนปรับแต่ง** งานรูปภาพคุ้มค่าเพราะตัวเลขก่อนและหลังมาจากเบราว์เซอร์ ไม่ใช่การเดา
